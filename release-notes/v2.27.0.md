# Manfaz VPN 2.27.0

The headline here is that TUN mode works. It had been reporting a healthy tunnel while carrying
nothing, which is the worst way for something to fail, and the cause turned out to be three
separate defects in the configuration the app generates. Alongside that, Xray is now the engine
a fresh install starts on.

## TUN said connected and carried nothing

Three things were wrong at once, each enough on its own to leave you with a tunnel that looked
up and moved no traffic.

**Sniffing ran too late.** The rule that recognises DNS matches on protocol, and protocol is
only known once a connection has been sniffed. That sniff step sat below the DNS rule, so the
rule never matched and queries left as plain UDP aimed at whatever resolver Windows had. On a
VLESS outbound using the vision flow there is nowhere for that UDP to go. Sniffing now runs
first, with a port based fallback underneath it for traffic that cannot be sniffed at all.

**Bootstrap lookups deadlocked against the tunnel.** Resolving the proxy server's own hostname
was left to the default route, and in a TUN configuration the default route is the proxy. The
lookup needed the tunnel, the tunnel needed the lookup. Those queries are now pinned to the
direct outbound, which auto interface detection sends out over the physical adapter.

**The wrong network stack.** The tunnel was built on the system stack, which is the least
reliable of the three on Windows. It now uses the mixed stack, pairing gVisor's TCP
implementation with the system UDP path.

The generated configuration also declares its default resolver explicitly, which settles an
ambiguity sing-box has been warning about since 1.12 and will drop in 1.14.

I want to be straight about the limits of this: these fixes were validated against the real
sing-box binary and reviewed against how the tunnel is actually assembled, but a live Windows
TUN session is not something I can run here. If TUN still misbehaves for you, say so and I will
keep digging.

## Xray is the default engine

New installations now start on Xray, with sing-box as the second engine. Xray covers VLESS,
VMess, Trojan and Shadowsocks, which is the overwhelming majority of what people actually
connect with.

sing-box has not gone anywhere and is still required for TUN, Hysteria2, TUIC and AnyTLS.
Picking any of those asks whether to switch engines for that connection instead of failing
without explanation.

If you already had an engine selected, updating leaves it alone. Only a fresh install picks up
the new default.

## AI Settings button

The apply button had dark text on a green fill, and in Persian it sat on the far right of the
row where it read as an afterthought rather than the thing to press.

The fill is deeper now and the label is white, which clears contrast properly. In Persian the
row lays out left to right so the button comes first, on the left, with its note beside it. The
card's text stays right aligned as it should.

## Repository tidying

Temporary branches were accumulating. Each release is started by pushing a `release/v*` branch,
and every one of those was still sitting there afterwards along with an old feature branch.

The release workflow now deletes them itself. After publishing, it removes any `release/*` or
`claude/*` branch whose tip is already contained in the default branch, checked through the
compare API so a branch holding unmerged work is left alone.

## Installing

Windows 10 or 11, 64 bit. Both engines ship inside the installer, so there is nothing to fetch
on first launch.

Run the app as Administrator if you want TUN, the kill switch, or system DNS changes. Without
elevation everything else still works over System Proxy.
